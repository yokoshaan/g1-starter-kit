# 記録と再生（教示して、もう一度やらせる）

テレオペで記録した腕の動きを、あとから再生します。

「教えた動きをそのまま繰り返せる。**でも物の位置が変わると失敗する**」ところまで体験できるので、模倣学習が何を解こうとしているのかが分かります。

---

## 記録の中身

`~/xr_teleoperate/teleop/utils/data/<名前>/episode_XXXX/data.json`

```jsonc
{
  "info": { "image": { "fps": 30.0 }, ... },
  "data": [
    {
      "idx": 0,
      "states":  { "left_arm": { "qpos": [7要素], ... }, "right_arm": {...}, ... },
      "actions": { "left_arm": { "qpos": [7要素], ... }, "right_arm": {...}, ... }
    },
    ...
  ]
}
```

| | |
|---|---|
| 単位 | ラジアン |
| 周波数 | 既定 30 Hz（`info.image.fps`） |
| `states` | ロボットの**実測**関節角 |
| `actions` | 逆運動学が出した**目標**関節角（既定でこちらを再生します） |

### ⚠️ 23DoF 機の記録には癖があります

`xr_teleoperate` は左右の腕を `q[:7]` と `q[-7:]` で切り出して保存します。

- **29DoF 機**（片腕 7 関節・計 14）→ 前半と後半にきれいに分かれます
- **23DoF 機**（片腕 5 関節・計 10）→ `[:7]` と `[-7:]` が**中央 4 要素で重なります**

そのまま「左右 7 関節」として再生すると全く別の姿勢になります。`tools/replay_arm.py` はこの重なりを検出して元の 10 要素に復元するので、**利用者側で気にする必要はありません**（`--dof` で明示もできます）。

## まず dry-run で確認する

**既定は dry-run です。** DDS には何も送らず、軌道のグラフと送信予定値だけを見せます。

```bash
./scripts/replay.sh --list      # 記録の一覧
./scripts/replay.sh             # 最新の記録を確認
./scripts/replay.sh ~/xr_teleoperate/teleop/utils/data/demo/episode_0000
```

出力例:

```
 記録の内容
  フレーム数 : 259   (8.6 秒 @ 30 Hz)
  データ源   : actions  (actions=IK解 / states=実測)
  機体判定   : 29DoF 機（腕 14 関節）  重なり誤差=2.10e+00
  関節                         最小       最大      可動域   リミット
  L_shoulder_pitch       -1.737   +0.033    1.770   [-3.09, +2.67]
  ...
```

ここで見るべき点:

- **フレーム数が 0 でないか** — 0 なら記録に失敗しています（`s` を押していない、または記録開始で落ちた）
- **機体判定が実機と合っているか** — 違えば `--dof 23` / `--dof 29` を明示
- **リミット逸脱の警告が無いか** — 逸脱分は再生時にクリップされます

グラフを画像に保存することもできます。

```bash
./scripts/replay.sh <episode> --no-plot --save-plot /tmp/traj.png
```

## 実機で再生する

```bash
./scripts/replay.sh <episode> --execute
```

### 動作の流れ

| | 内容 | 時間 |
|---|---|---|
| 1 | 制御権を 0 → 1 に渡す（姿勢は現在のまま） | 2 秒 |
| 2 | 現在姿勢 → 記録の初期姿勢へ線形補間 | 4 秒 |
| 3 | 記録軌道の再生 | 記録の長さ |
| 4 | 記録の初期姿勢へ戻す | 3 秒 |
| 5 | 姿勢をホールドしたまま制御権を返す | 2 秒 |

**中断は Enter**（または Ctrl+C）。**現在の姿勢を保ったまま**制御権を返すので、腕が落ちることはありません。

⚠️ **手順 2 で腕が大きく動くことがあります。** 現在の姿勢と記録の初期姿勢が離れているほど大きく動きます。最初の 4 秒を見ていて、危なければ即 Enter で止めてください。

### 触る関節

- 腕（23DoF なら 10、29DoF なら 14 関節）
- 腰は「現在の角度でホールド」します（`--waist none` で書き込みを止められます）
- **脚とハンドの姿勢は変えません**

## 指令トピックについて（ここが分かりにくい）

G1 の腕を動かす経路は 2 つあり、**ロボットの状態によってどちらを使うかが変わります**。

| トピック | 使える条件 | 中身 |
|---|---|---|
| `rt/arm_sdk` | **モーションコントローラが動いているとき** | 動いているコントローラから腕の制御権だけ分けてもらう。`motor_cmd[29].q` が制御権の重み（0〜1） |
| `rt/lowcmd` | デバッグ状態（コントローラ停止時） | 全身の低レベル指令 |

**`rt/arm_sdk` はモーションコントローラが止まっていると何も起きません。** 制御権を渡してくれる相手がいないためです。このとき、スクリプトは正常に完走して「再生成功」と表示するのに腕は動きません。

`tools/replay_arm.py` は既定（`--topic auto`）でロボットに問い合わせて選びます。

```
  トピック         : rt/lowcmd   （モーションコントローラが停止（デバッグ状態）= arm_sdk は効かない）
```

### `rt/lowcmd` を使うときの安全策

`rt/lowcmd` は**全身**の低レベル指令です。腕以外を空のまま送ると `q=0, kp=0, kd=0` が渡り、**脚が脱力します**（座位でも崩れます）。

そのため、このスクリプトは送信前に**全 29 関節を起動時の実測角度でロック**してから腕だけを上書きします。ゲインも `xr_teleoperate` と同じ分類（手首 40 / 肩肘 80 / その他 300）にしてあります。

```
  全 29 関節を現在角度でロックしました（腕以外は動きません）
```

このメッセージが出ていれば脱力対策が効いています。

## 主なオプション

```bash
./scripts/replay.sh <episode> --source states   # 実測値を再生（既定は actions）
./scripts/replay.sh <episode> --dof 29          # DoF を明示
./scripts/replay.sh <episode> --waist none      # 腰に一切書き込まない
./scripts/replay.sh <episode> --execute --topic rt/arm_sdk    # トピックを明示

# 細かい調整は tools/replay_arm.py を直接呼ぶ
python3 tools/replay_arm.py --help
```

## ここから先

再生は「同じ初期配置でしか成功しない」ことがすぐ分かります。物を少しずらすと掴めません。

そこを乗り越えるのが模倣学習で、記録した `states` / `actions` はそのための学習データになります。進み方は [07-next-steps.md](07-next-steps.md) を参照してください。
